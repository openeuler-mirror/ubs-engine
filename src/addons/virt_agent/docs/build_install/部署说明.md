# 部署说明

## 1. 概述

virt_agent 以 UBSE 插件形式部署，随 UBSE 服务运行（无独立进程），面向虚拟化/容器化场景，为云管生态（如 MatrixServer）提供内存借用、归还、迁移等内存逃生能力。

发布件组成如下：

| RPM 包                                                       | 说明                                                                           | 安装建议                                                 |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------ | -------------------------------------------------------- |
| `ubs-engine-virtagent-<version>-<release>.aarch64.rpm`       | 主程序包（插件库、客户端 SDK 运行库、配置文件、默认策略库）                    | 必须安装                                                 |
| `python3-ubs-engine-<version>-<release>.noarch.rpm`          | Python SDK 包（UBSE 共享包，合并打包 UBSE 框架 SDK 与 virt_agent Python 接口） | 虚机场景必须安装（场景设置依赖）；容器场景按调用语言按需 |
| `ubs-engine-virtagent-devel-<version>-<release>.aarch64.rpm` | 开发包（头文件与开发软链）                                                     | 可选安装（SDK 二次开发时）                               |

## 2. 安装

### 2.1 系统要求

**软硬件要求：**

| 项目     | 要求                           |
| -------- | ------------------------------ |
| 操作系统 | openEuler 24.03 LTS 或更高版本 |
| CPU 架构 | aarch64                        |
| 内存     | ≥ 64GB                         |
| 硬件平台 | 950 UB 硬件（UB 建链）         |
| 用户权限 | 安装与管理需 `root` 权限       |

**依赖运行时库：**

virt_agent 运行所依赖的系统库（如 `glibc`、`systemd`、`libxml2`、`numactl-libs` 等）由操作系统提供；`libboundscheck`、UBSE 框架库等随 `ubs-engine` 主包自动安装，无需单独处理。

### 2.2 组件依赖

virt_agent 作为 UBSE 插件运行，部署依赖：

- 已完整安装的 `ubs-engine` 主包（安装部署见 [UBSE 安装说明](../../../../../docs/zh/ubse_installation.md)）；
- mempooling（RMRS）插件：virt_agent 的内存借用/迁移能力依赖该插件，需先行安装（安装部署见 [RMRS 用户指南](../../../rmrs/docs/User_Guide.md)）；
- Python 运行环境（仅使用 Python SDK 时需要）。

### 2.3 安装 RPM 包

> 主程序包需在所有集群节点安装，以下命令需在每个节点执行（可使用批量运维工具分发）。
> 前提：mempooling（RMRS）插件须已按 2.2 节要求先行安装。

从本地 RPM 文件安装时，推荐一条命令同时安装主程序包和 Python SDK 包（dnf 自动处理依赖与顺序）；若已配置 yum 源，也可直接按包名安装：

```bash
sudo dnf install -y ubs-engine-virtagent-<version>-<release>.aarch64.rpm python3-ubs-engine-<version>-<release>.noarch.rpm
```

若使用 `rpm` 命令，请注意依赖顺序（先主程序包，后 Python SDK 包）：

```bash
sudo rpm -ivh ubs-engine-virtagent-<version>-<release>.aarch64.rpm
sudo rpm -ivh python3-ubs-engine-<version>-<release>.noarch.rpm
```

### 2.4 安装开发包（可选）

SDK 二次开发（编译链接 `libubs-virt-agent.so`、引用头文件）时安装：

```bash
sudo dnf install -y ubs-engine-virtagent-devel-<version>-<release>.aarch64.rpm
```

> 开发包依赖同版本主程序包，请确保先完成 2.3 节安装。

### 2.5 安装结果

**主程序包：**

| 路径/文件                                  | 说明                                                                                                                                          |
| ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `/usr/lib64/libvirtagent.so`               | **virt_agent 插件主体（服务端）**（由 ubse 进程动态加载，注册 IPC 接口并实现内存借用/归还/迁移能力）                                          |
| `/etc/ubse/plugins/plugin_virt_agent.conf` | 插件配置文件：逃生水位线（borrow/high watermark）、单块借用内存规格（min/maxPerBorrowSize）、逃逸算法库路径（escape.algorithm.dir）等决策参数 |
| `/etc/ubse/plugins/auth-virt_agent.conf`   | SDK 鉴权配置文件：定义 SDK 调用方的用户、角色与权限映射（如 `nova=vm_nova`、`vm_nova=vm.migrate,vm.case_conf`）                               |
| `/usr/lib64/libubs-virt-agent.so.xx.xx.xx` | **客户端 SDK 运行库**：供云管/用户程序通过其 C/Go/Python 接口调用借用、归还、迁移、查询等能力（经 UDS IPC 与服务端交互）                      |
| `/usr/lib64/libubs-virt-agent.so.1`        | 软链接，指向 `libubs-virt-agent.so.xx.xx.xx`                                                                                                  |
| `/usr/lib64/libstrategy.so`                | 默认逃逸策略算法库：内存紧张时按该算法执行借用/迁移决策（可通过 escape.algorithm.dir 替换为自定义算法）                                       |

**Python SDK 包（`python3-ubs-engine`，UBSE 共享，安装于 `/usr/lib/python3.11/site-packages/ubse/` 下）：**

| 目录/文件 | 说明                                                                                                                                                                                                                                                                                         |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 顶层模块  | 高层封装：`ubs_virt_case_conf.py`（场景配置查询脚本，可直接运行）、`ubs_virt_agent_fragmentation.py`（内存碎片借用/迁移/归还/回滚/任务查询）、`ubs_virt_agent_query.py`（节点/虚机查询）、`ubs_virt_agent_vm_migrate.py`（虚机迁移）、`ubs_virt_agent_case_conf.py`、`ubs_virt_agent_log.py` |
| `ffi/`    | 逐接口 ctypes 封装：内存借用（`ubs_virt_agent_mem_borrow.py` 等）、归还（`ubs_virt_agent_mem_return.py`）、迁移、回滚、任务查询、反亲和、换页使能、场景配置读写等                                                                                                                            |
| `models/` | 数据结构定义（`BorrowParamT`、`CaseConfInfoT` 等）                                                                                                                                                                                                                                           |

## 3. 配置与服务启停

### 3.1 修改插件准入配置

编辑 `/etc/ubse/ubse_plugin_admission.conf`，取消 virt_agent 和 mempooling 的注释，示例如下：

```ini
# virt_agent plugin. Default value: 205
virt_agent=205
# mempooling plugin. Default value: 777
mempooling=777
# ucache plugin. Default value: 778
# ucache=778
```

> **注意：**
>
> 1. virt_agent 依赖 mempooling（RMRS）插件，需先安装 mempooling（RMRS）插件；
> 2. 修改配置文件后，需重启 UBSE 服务，重启命令见 [3.2](#32-服务启停与开机自启)。

### 3.2 服务启停与开机自启

virt_agent 作为 UBSE 的插件随 UBSE 服务启动：

```bash
# 启动服务
sudo systemctl start ubse

# 停止服务
sudo systemctl stop ubse

# 重启服务（修改配置后执行）
sudo systemctl restart ubse

# 查看状态
sudo systemctl status ubse

# 开机自启
sudo systemctl enable ubse
```

## 4. 设置场景（仅虚机场景，必选）

virt_agent 的运行场景由配置项 `virt.sceneType` 指定（默认 `1`，即虚机场景；修改 `plugin_virt_agent.conf` 后需重启 ubse 生效）：

- **虚机场景（`virt.sceneType=1`）**：支持超分（overCommitment）与内存碎片（memFragmentation）两种业务模式，安装后必须配置其一（见 4.1~4.3）；
- **容器场景（`virt.sceneType=0`）**：无需配置场景，容器内存借用通过容器 SDK 接口显式触发（水位线注入与借用/迁移/归还接口），本节的场景配置与查询均不适用。

### 4.1 选择场景并编写设置脚本

#### 4.1.1 超分场景（overCommitment）

内存使用率超过水位线阈值时，自动触发内存借用/归还逃生。

参数取值：

| 参数             | 取值             | 说明                          |
| ---------------- | ---------------- | ----------------------------- |
| `caseType`       | `overCommitment` | 场景类型                      |
| `overCommitment` | 如 `1.25`        | 超分比例，取值范围 (1.0, 1.8] |

#### 4.1.2 内存碎片场景（memFragmentation）

节点 CPU 充足、内存不足时，借用邻居节点内存创建虚拟机。

参数取值：

| 参数             | 取值               | 说明                       |
| ---------------- | ------------------ | -------------------------- |
| `caseType`       | `memFragmentation` | 场景类型                   |
| `overCommitment` | `1.00`             | 固定值，该场景下必须为 1.0 |

#### 4.1.3 编写场景设置脚本

> 执行脚本的用户需在 `auth-virt_agent.conf` 权限白名单中且具备 `vm.case_conf` 权限；
> 场景配置存储于各节点本地，需在**每个集群节点**分别执行。

在任意路径（如 `/root`）创建脚本 `test_case_conf_set.py`，内容如下（按 4.1.1 / 4.1.2 修改 `param` 取值）：

```python
from ubse.ffi.ubs_virt_agent_case_conf_set import UbsVirtAgentCaseConfSet

def set_case_conf():
    case_conf_set = UbsVirtAgentCaseConfSet()
    try:
        case_conf_set.ubs_virt_agent_initialize()
        param = {
            "caseType": "memFragmentation",   # 超分场景填 "overCommitment"
            "overCommitment": 1.00            # 超分场景按需填写，如 1.25
        }
        return case_conf_set.ubs_case_conf_set(param)
    except Exception as e:
        msg = f"Failed to set_case_conf, error: {e}"
        print(msg)
        raise RuntimeError(msg) from e
    finally:
        case_conf_set.ubs_virt_agent_finalize()

if __name__ == '__main__':
    ret_code = set_case_conf()

    print(f"{ret_code = }")
```

### 4.2 执行场景设置脚本

> **警告**：`rm -rf /var/lib/ubse/data/*` 会清空 ubse 全部本地数据（含借用状态、迁移状态与场景配置）。
> 仅在首次部署配置、或确认无在途借用/迁移业务时执行；生产环境已运行业务时请勿执行，
> 此时应先通过 4.3 查询当前场景，若已是目标场景则无需重复设置。

在 UBSE 服务启动后，进入脚本所在目录执行以下命令注入场景信息：

```bash
rm -rf /var/lib/ubse/data/*    # 清空 ubse 数据目录，确保场景信息被正确注入（见上方警告）
python3 test_case_conf_set.py  # 执行脚本注入场景，返回值 ret=0 即执行成功
sudo systemctl restart ubse    # 重启 UBSE 服务，确保场景信息生效
```

### 4.3 查询场景

执行场景配置查询脚本，确认输出中 `case_type` 与 `over_commitment` 符合预期：

```bash
python3 /usr/lib/python3.11/site-packages/ubse/ubs_virt_case_conf.py
```

**预期结果：**

| 场景         | `case_type`        | `over_commitment` |
| ------------ | ------------------ | ----------------- |
| 内存碎片场景 | `memFragmentation` | `1.0`             |
| 超分场景     | `overCommitment`   | `1.25`            |

字段含义与通路异常判断见 [5.3 SDK 通路验证](#53-sdk-通路验证)。

> 容器场景（`virt.sceneType=0`）未注册场景配置接口，不支持本查询，无需关注场景配置。

## 5. 部署验证

### 5.1 服务与插件加载状态

```bash
# 检查服务状态，应输出 "active"
systemctl is-active ubse

# 检查 virt_agent 插件是否被 ubse 成功加载
journalctl -u ubse | grep -i virt_agent
```

**预期结果**：`systemctl is-active ubse` 输出 `active`；`journalctl -u ubse | grep -i virt_agent` 能检索到 virt_agent 插件加载日志。若第二条无输出，说明插件未加载，请检查准入配置（见 3.1）并重启服务。

### 5.2 依赖插件检查

virt_agent 的借用/迁移能力依赖 mempooling（RMRS）插件，需确认该插件已随 ubse 加载：

```bash
journalctl -u ubse | grep -i mempooling
```

**预期结果**：能检索到 mempooling 插件的加载日志。若无输出，请确认已安装并准入 mempooling 插件（见 3.1）。

### 5.3 SDK 通路验证

安装 Python SDK 包后，执行 [4.3 查询场景](#43-查询场景)中的查询命令即可验证 SDK 到 UBSE 服务的 IPC 通路，能正常返回场景信息即通路正常。

**预期结果**：命令退出码为 `0`，输出以 `#####` 包裹的场景配置信息，并逐项打印字段，示例如下（字段值随环境配置不同）：

```text
#####{'case_type': 'overCommitment', 'over_commitment': 1.25, 'migrate_water_line': 85, 'index': 0, 'host_id': '0'}#####
case_type: overCommitment, over_commitment: 1.25, migrate_water_line: 85, index: 0, host_id: 0,
```

各字段含义：

| 字段                 | 说明                                                                                                                               |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `case_type`          | 当前生效的场景类型（`overCommitment` 超分场景 / `memFragmentation` 内存碎片场景）；未配置场景时查询报错，需先按第 4 章完成场景设置 |
| `over_commitment`    | 超分比例（浮点数）：与 4.1.1 场景设置时的取值一致（示例 `1.25`，取值范围 (1.0, 1.8]）；`1.00` 表示不超分                           |
| `migrate_water_line` | 虚机迁移水位线（%，取值同 high.watermark）                                                                                         |
| `index`              | 场景序号                                                                                                                           |
| `host_id`            | 主机 ID（节点 ID）                                                                                                                 |

若输出 `Failed to get case conf info, error: ...` 且退出码非 `0`：请先确认场景已配置（见第 4 章）；若场景已配置仍失败，则说明 SDK 与 UBSE 服务 IPC 通路异常。

### 5.4 查看日志

```bash
# 方式一：查看 systemd 日志
journalctl -u ubse -f

# 方式二：查看日志文件
tail -f /var/log/ubse/virt_agent_plugin.log
```

## 6. 升级与卸载

### 6.1 升级

```bash
# 升级已安装的包（按实际安装情况选择）
sudo dnf update -y ubs-engine-virtagent ubs-engine-virtagent-devel python3-ubs-engine
# 或使用本地 rpm 升级（替换为实际版本号）
sudo rpm -Uvh ubs-engine-virtagent-<version>-<release>.aarch64.rpm \
             ubs-engine-virtagent-devel-<version>-<release>.aarch64.rpm \
             python3-ubs-engine-<version>-<release>.noarch.rpm

# 升级后重启服务以加载新版本插件
sudo systemctl restart ubse
```

> 使用本地 rpm 升级时请只传入本组件的包文件，避免通配符（如 `ubs-engine*.rpm`）误升级同目录下其他组件的包。

### 6.2 卸载

**方式一：单独卸载 virt_agent**

```bash
# 如安装了开发包，先卸载开发包
sudo rpm -evh ubs-engine-virtagent-devel
sudo rpm -evh ubs-engine-virtagent
```

**方式二：卸载 UBSE 全部组件（含 virt_agent）**

```bash
# 1. 停止服务
sudo systemctl stop ubse
# 2. 卸载插件包（如已安装；先卸载 virt_agent，再卸载其依赖的 rmrs）
sudo rpm -evh ucache
sudo rpm -evh ubs-engine-virtagent
sudo rpm -evh rmrs
# 3. 卸载 UBSE 所有包
sudo rpm -evh python3-ubs-engine
sudo rpm -evh ubs-engine-client-devel
sudo rpm -evh ubs-engine-client-libs
sudo rpm -evh ubs-engine
```

> 卸载不会删除 `/var/lib/ubse/` 和 `/var/log/ubse/` 中的数据，如需清理请手动删除。
