# UBS-Engine 编码规范文档

> 本文档定义 UBS-Engine 项目的代码规范,涵盖格式化、命名、注释、版权、头文件、编译警告、静态分析、测试规范等,作为代码编写与评审的依据。
> 所有规范均由工具链强制执行(详见第 11 章工具链)。

## 1. 语言标准

| 语言 | 标准 | 配置 |
|------|------|------|
| C | C11 | `CMAKE_C_STANDARD 11` + `CMAKE_C_STANDARD_REQUIRED ON` + `CMAKE_C_EXTENSIONS NO` |
| C++ | C++17 | `CMAKE_CXX_STANDARD 17` + `CMAKE_CXX_STANDARD_REQUIRED ON` + `CMAKE_CXX_EXTENSIONS OFF` |

**强制要求**:必须使用 C11/C++17 标准,禁用编译器扩展(`EXTENSIONS OFF`)。

## 2. 代码格式化

**配置文件**:[.clang-format](../../.clang-format)

**基础风格**:Google,针对项目约定做定制。

### 2.1 缩进与行宽

| 配置项 | 值 | 说明 |
|--------|-----|------|
| `IndentWidth` | 4 | 4 空格缩进 |
| `TabWidth` | 4 | Tab 宽度 4 |
| `UseTab` | Never | **禁用 Tab**,仅用空格 |
| `ColumnLimit` | 120 | 行宽上限 120 |
| `ContinuationIndentWidth` | 4 | 续行缩进 4 |
| `ConstructorInitializerIndentWidth` | 4 | 构造函数初始化列表缩进 4 |
| `AccessModifierOffset` | -4 | `public`/`private` 与 `class` 关键字对齐 |

### 2.2 大括号风格(混合 Allman + K&R)

采用 `BreakBeforeBraces: Custom`:

| 元素 | 风格 | 示例 |
|------|------|------|
| 函数定义 | **Allman**(大括号另起一行) | `void Foo()\n{\n    ...\n}` |
| 控制语句(if/for/while) | **K&R**(大括号不换行) | `if (cond) {\n    ...\n}` |
| 类/结构体/枚举/命名空间 | K&R(不换行) | `class Foo {\n    ...\n};` |
| `else` | 不换行 | `} else {` |
| `catch` | 不换行 | `} catch (...) {` |

### 2.3 短语句策略

| 配置项 | 值 | 说明 |
|--------|-----|------|
| `AllowShortBlocksOnASingleLine` | Empty | 仅空块可单行 |
| `AllowShortFunctionsOnASingleLine` | Empty | 仅空函数体可单行 |
| `AllowShortIfStatementsOnASingleLine` | Never | **禁止**短 if 单行 |
| `AllowShortLoopsOnASingleLine` | false | **禁止**短循环单行 |
| `AllowShortCaseLabelsOnASingleLine` | false | **禁止**短 case 单行 |
| `AllowShortEnumsOnASingleLine` | false | **禁止**短 enum 单行 |
| `AllowShortLambdasOnASingleLine` | Inline | 仅内联 lambda 可单行 |

### 2.4 指针与引用

- `PointerAlignment: Right`(指针 `*` 靠近变量名)
- `DerivePointerAlignment: false`(不自动推导)
- 示例:`int *p`、`const std::string &name`

### 2.5 Include 管理

- `IncludeBlocks: Preserve`(保持原样不自动重排)
- `SortIncludes: true`(同 block 内排序)
- `SortUsingDeclarations: true`(using 声明排序)

**Include 优先级**(从高到低):

| 优先级 | 正则 | 说明 |
|--------|------|------|
| 1 | `<.*\.h>` | C 系统头 |
| 2 | `^<.*` | C++ 系统头 |
| 3 | `"rack_def.h"` | rack_def.h 特殊处理 |
| 4 | `"rack_*.h"` | rack 系列头 |
| 5 | 其他 | 项目内头文件 |

### 2.6 其他关键项

| 配置项 | 值 |
|--------|-----|
| `Standard` | `c++17` |
| `SpaceBeforeParens` | `ControlStatements`(控制语句括号前加空格) |
| `FixNamespaceComments` | `true`(自动修复命名空间结束注释) |
| `NamespaceIndentation` | `None`(命名空间内不额外缩进) |
| `ReflowComments` | `false`(不重排注释) |
| `MaxEmptyLinesToKeep` | 1 |
| `IndentCaseLabels` | `true` |

## 3. 命名规范

**强制执行**:由 [.clang-tidy](../../.clang-tidy) 的 `readability-identifier-naming` 检查项强制。

### 3.1 标识符命名

| 类型 | 风格 | 前缀/后缀 | 示例 |
|------|------|-----------|------|
| 类 / 结构体 | CamelCase | - | `UbseComModule`、`UbseNodeApi`、`UbseContext` |
| 枚举类型 | CamelCase | - | `UbseModuleCode`、`UbseSsuNsState` |
| 函数 / 方法 | CamelCase | - | `Initialize()`、`StartComService()`、`RegisterVerifyMsgCb()` |
| 局部变量 | camelBack | - | `nodeId`、`remoteIp`、`retCode` |
| 成员变量 | camelBack | `_` 后缀 | `rpcServer_`、`queueRef_`、`ctx_` |
| 全局变量 | camelBack | `g_` 前缀 | `g_ubseContext`、`g_globalStop`、`g_globalCv` |
| 全局常量 | UPPER_CASE | - | `DEFAULT_TCP_SERVER_PORT`、`MASTER_RPC_SERVER_NAME` |
| 枚举常量 | UPPER_CASE | - | `UBSE_OK`、`UBSE_ERROR` |
| 宏定义 | UPPER_CASE | - | `UBSE_LIKELY`、`UBSE_UNLIKELY`、`UBSE_RPC_RETRY_TIME` |
| constexpr 数字常量 | UPPER_CASE | `NO_` 前缀 | `NO_0`、`NO_1`、`NO_1024`、`NO_NEGATIVE_1` |

### 3.2 文件命名

| 类型 | 规范 | 示例 |
|------|------|------|
| 头文件(C++) | `ubse_<module>.h` | `ubse_com.h`、`ubse_logger.h`、`ubse_ssu_service.h` |
| 源文件(C++) | `ubse_<module>.cpp` | `ubse_com.cpp`、`ubse_main.cpp` |
| C 源文件(SDK) | `ubs_engine.c` / `ubs_*.c` | `ubs_engine.c`、`ubs_error.c`(SDK 层用 `ubs_` 前缀) |
| 测试文件 | `test_ubse_<module>.cpp/.h` | `test_ubse_logger.h`、`test_ubse_com.cpp` |
| Mock 文件 | `mock_<name>.cpp/.h` | `mock_module.h`、`mock_dependency_module.cpp` |
| CMake 文件 | `CMakeLists.txt` | 每个目录下均有 |

### 3.3 命名空间

- **顶层命名空间**:`ubse`
- **层级命名空间**:`ubse::<module>::<submodule>`

**示例**:

```cpp
namespace ubse::com { ... }              // 通信
namespace ubse::log { ... }              // 日志
namespace ubse::context { ... }          // 上下文
namespace ubse::node::api { ... }        // 节点 API
namespace ubse::common::def { ... }      // 公共定义
namespace ubse::utils { ... }            // 工具
namespace ubse::module { ... }           // 模块基类
namespace ubse::ut::<module> { ... }     // 单元测试
```

**命名空间结束注释**(由 `FixNamespaceComments: true` 自动维护):

```cpp
} // namespace ubse::com
```

### 3.4 类型别名

使用 `using` 而非 `typedef`:

```cpp
// 正确
using UbseResult = uint32_t;
using IpAddress = std::pair<std::string, uint16_t>;
using UbseComBaseMessageHandlerPtr = std::shared_ptr<UbseComBaseMessageHandler>;

// 错误(禁用)
typedef uint32_t UbseResult;
```

## 4. 头文件规范

### 4.1 头文件保护

**统一使用 `#ifndef` 保护**(非 `#pragma once`)。

**命名规则**:`<大写项目前缀>_<文件名>_H`

```cpp
#ifndef UBSE_XXX_H
#define UBSE_XXX_H

// includes
// declarations

#endif // UBSE_XXX_H
```

**示例**:

| 文件 | 头文件保护宏 |
|------|--------------|
| `src/include/ubse_def.h` | `UBSE_DEF_H` |
| `src/include/ubse_common_def.h` | `UBSE_COMMON_DEF_H` |
| `src/include/plugin_services/ssu/ubse_ssu_service.h` | `UBSE_SSU_SERVICE_H` |

**注意**:`#endif` 后必须带注释标注宏名。历史代码中存在少量拼写不一致(如 `UBAE_`/`USBE_`),新代码统一为 `UBSE_` 前缀。

### 4.2 Include 顺序

按优先级从高到低:

```cpp
// 1. 对应的头文件(若为 .cpp)
#include "ubse_xxx.h"

// 2. C 系统头
#include <stdint.h>
#include <unistd.h>

// 3. C++ 系统头
#include <memory>
#include <string>
#include <vector>

// 4. 项目内头文件
#include "ubse_def.h"
#include "ubse_logger.h"
```

### 4.3 前向声明

优先使用前向声明减少 include 耦合:

```cpp
// 头文件中前向声明
namespace ubse::com {
class UbseComModule;
}

// 源文件中 include 完整定义
#include "ubse_com_module.h"
```

## 6. 注释规范

### 6.1 注释风格

| 类型 | 风格 | 用途 |
|------|------|------|
| 单行注释 | `//` | 简短说明 |
| 多行注释 | `/* ... */` | 版权头、详细说明 |
| 文档注释 | `/** ... */` | Doxygen 文档(类/函数/枚举) |

### 6.2 Doxygen 文档注释

公共接口(服务契约、对外 API)**必须**使用 Doxygen 注释:

```cpp
/**
 * @brief 分配 SSU 存储空间
 *
 * 根据请求参数分配指定数量和大小的命名空间,支持顺序分配和
 * 分布式分配两种策略。
 *
 * @param req     分配请求参数
 * @param identity 调用方身份信息
 * @param result  [输出] 分配结果
 * @return uint32_t 错误码
 * @retval 0 成功
 * @retval 非零 失败
 *
 * @note 当 nsNum 为 1 时,strategy 参数不生效
 * @see UbseSsuAllocSpaceReq, UbseSsuAllocResult
 */
virtual uint32_t AllocSpace(const UbseSsuAllocSpaceReq &req, ...) = 0;
```

### 6.3 TODO 注释

```cpp
// TODO: 支持多租户配额管理
// FIXME: 修复并发场景下的状态机转换问题
```

### 6.4 命名空间结束注释

由 `FixNamespaceComments: true` 自动维护:

```cpp
namespace ubse::ssu::service {
// ...
} // namespace ubse::ssu::service
```

## 7. 编译警告配置

**配置文件**:[scripts/cmake/building.cmake](../../scripts/cmake/building.cmake)

### 7.1 基础警告 flags(`BASE_BUILD_FLAGS`)

| Flag | 说明 |
|------|------|
| `-Wall` | 启用大多数警告 |
| `-Wextra` | 启用额外警告 |
| `-Wconversion` | 类型转换警告 |
| `-Wshadow=local` | 局部变量隐藏警告 |
| `-Wfloat-equal` | 浮点数相等比较警告 |
| `-fsigned-char` | char 默认为 signed char |
| `-fno-common` | 全局变量同名警告 |

**注意**:
- 未启用 `-Werror`(警告不导致编译失败)
- `-Wpedantic` 被注释(不强制严格 ISO 标准)

### 7.2 安全 flags(`SECURE_BUILD_FLAGS`)

| Flag | 说明 |
|------|------|
| `-fPIC` | 位置无关代码 |
| `-fPIE` | 位置无关可执行文件 |
| `-fstack-protector-strong` | 强栈保护 |
| `-D_FORTIFY_SOURCE=2` | 源码级加固(非 Debug) |
| `-Wl,-z,noexecstack` | 栈不可执行 |
| `-Wl,-z,relro,-z,now` | GOT 只读 |

### 7.3 Debug/Release 组合

| 模式 | Flags |
|------|-------|
| **DEBUG_FLAGS** | BASE + SECURE + `-O0 -ggdb3 -fno-omit-frame-pointer` |
| **RELEASE_FLAGS** | BASE + SECURE |

### 7.4 Sanitizer 支持

通过 `build.sh` 选项启用:

| 选项 | Sanitizer | 说明 |
|------|-----------|------|
| `--asan` | AddressSanitizer | 内存错误检测 |
| `--lsan` | LeakSanitizer | 内存泄漏检测 |
| `--tsan` | ThreadSanitizer | 线程竞争检测 |
| `--ubsan` | UndefinedBehaviorSanitizer | 未定义行为检测 |

ASAN 在 `ubse` 可执行文件级别单独配置(`src/CMakeLists.txt`):

```
-fsanitize=address
-fsanitize-recover=address
-fsanitize=leak
-static-libasan
-fno-omit-frame-pointer
```

## 9. 静态分析

**配置文件**:[.clang-tidy](../../.clang-tidy)

### 9.1 策略

**白名单模式**:先 `-*` 禁用全部,再逐项启用,避免版本升级引入意外告警。

### 9.2 头文件过滤

```
HeaderFilterRegex: '^(src|plugin|include|test)/.*\.h$'
```

仅对项目源码头文件进行诊断。

### 9.3 启用的检查类别

| 类别 | 检查项 | 说明 |
|------|--------|------|
| **bugprone** | argument-comment, dangling-handle, fold-init-type, forward-declaration-namespace, forwarding-reference-overload, easily-swappable-parameters, shadow, sizeof-*, string-constructor, undefined-memory-manipulation, unused-return-value, **use-after-move** | 常见编程错误 |
| **cert** | err58-cpp | 静态初始化抛异常 |
| **clang-analyzer** | `-*`(全部启用) | Clang 静态分析器 |
| **concurrency** | mt-unsafe | 多线程不安全函数 |
| **cppcoreguidelines** | avoid-non-const-global-variables, missing-std-forward, pro-type-cstyle-cast, pro-type-reinterpret-cast, pro-type-member-init, special-member-functions, virtual-class-destructor | C++ 核心准则 |
| **google** | build-using-namespace, explicit-constructor | Google 规范 |
| **misc** | definitions-in-headers, redundant-expression, use-anonymous-namespace | 杂项 |
| **modernize** | `-*`(全部启用,排除 `use-auto` 和 `use-trailing-return-type`) | 现代 C++ 特性 |
| **performance** | 13 项性能检查 | 性能优化 |
| **readability** | braces-around-statements, duplicate-include, function-size, identifier-naming, redundant-string-init | 可读性 |

### 9.4 错误级别警告(强制修复)

```
WarningsAsErrors: 'bugprone-use-after-move'
```

**移动后使用**(`use-after-move`)必须修复,否则视为错误。

### 9.5 函数大小限制

```
readability-function-size.StatementThreshold: '50'
```

函数体不超过 **50 条语句**。

### 9.6 关键 CheckOptions

| 检查项 | 配置 | 说明 |
|--------|------|------|
| `bugprone-easily-swappable-parameters.MinimumLength` | 4 | 参数类型相似度阈值 |
| `cppcoreguidelines-avoid-non-const-global-variables.AllowThreadLocal` | true | 允许 thread_local |
| `cppcoreguidelines-special-member-functions.AllowSoleDefaultDtor` | true | 允许仅有默认析构 |
| `modernize-use-using.IgnoreExternC` | true | extern "C" 块内忽略 |
| `performance-unnecessary-value-param.AllowedTypes` | `[Pp]ointer$;[Pp]tr$;[Rr]ef(erence)?$` | 指针/引用类型允许按值传递 |

## 10. 测试规范

**测试框架**:GoogleTest (GTest) + GMock + MockCpp

### 10.1 测试目录结构

```
test/
├── UT/     # 单元测试(镜像 src/ 结构)
├── IT/     # 集成测试
├── PT/     # 性能测试
└── FUZZ/   # 模糊测试
```

### 10.2 测试命名规范

**文件命名**:
- 测试文件:`test_ubse_<module>.cpp` / `test_ubse_<module>.h`
- Mock 文件:`mock_<name>.cpp` / `mock_<name>.h`

**TestSuite 与 TestName**:

| 类型 | 命名风格 | 示例 |
|------|----------|------|
| TestSuite | `Test<Module>`(CamelCase) | `TestUbseLogger`、`TestUbseCom`、`TestUbseSsuScheduler` |
| TestName | CamelCase 描述性命名 | `ConvertStrToUInt32_Valid`、`CreateInstance_Wait`、`RunAllSuccess` |

**测试命名空间**:

```cpp
namespace ubse::ut::<module> {  // 如 ubse::ut::log、ubse::ut::com
class TestXxx : public testing::Test { ... };
}
```

### 10.3 测试夹具结构(标准模板)

```cpp
class TestUbseXxx : public testing::Test {
public:
    TestUbseXxx();
    void SetUp() override;
    void TearDown() override;
};
```

- 优先使用 `TEST_F`(夹具测试),简单场景可用 `TEST`

### 10.4 测试宏(`add_ut`)

**定义位置**:[scripts/cmake/utils.cmake](../../scripts/cmake/utils.cmake)

```cmake
macro(add_ut module)
    set(UT_BINARY ${CMAKE_PROJECT_NAME}_${module}_ut)  # 如 ubs-engine_ubse_log_ut
    # 自动 GLOB_RECURSE 扫描 *.cpp/*.h
    # 链接 GTest::gmock_main、mockcpp、ubse_plugin(whole-archive)、被测模块
    target_compile_options(${UT_BINARY} PRIVATE -fno-access-control ${DEBUG_FLAGS})
    # -fno-access-control:打破访问权限,允许测试私有成员
    # 输出 xml 报告到 coverage/${module}_detail.xml
    gtest_discover_tests(${UT_BINARY} PROPERTIES LABELS "${module}")
endmacro()
```

### 10.5 测试运行命令

```shell
bash build.sh ut                                    # 运行所有 UT
bash build.sh ut -- --gtest_filter="TestSuite.*"    # 运行指定套件
bash build.sh ut -- --gtest_filter="TestSuite.Case" # 运行单个用例
bash build.sh ubse_http_ut                          # 运行某模块 UT
bash build.sh ut -C                                 # 生成覆盖率报告
bash build.sh ut -C -H                              # 覆盖率 + 启动 HTTP 服务
```

### 10.6 覆盖率要求

- **只有 100% UT 通过才允许生成覆盖率报告**(CI 强制校验)
- 工具链:gcov + lcov + genhtml
- 默认输出:`cmake-build-debug/coverage/index.html`
- 配置文件:[.lcovrc](../../.lcovrc)

### 10.7 测试编译特殊处理

- 测试目标自动启用 Debug 模式(`build_type='Debug'`)
- `-fno-access-control`:允许测试访问私有成员(谨慎使用)
- `--gtest_output=xml:...`:输出 JUnit XML

## 11. 工具链与自动化

### 11.1 Pre-commit Hooks

**配置文件**:[.pre-commit-config.yaml](../../.pre-commit-config.yaml)

采用 `pre-commit` 框架 + 本地仓库 hooks,共 5 个钩子:

| ID | 名称 | 触发文件 | 命令 | 说明 |
|----|------|----------|------|------|
| `run-build` | Run Release Build | 非 test/ 下的 `.h/.c/.cpp/.sh/.cmake/CMakeLists.txt` | `bash build.sh` | 提交源码时执行 Release 构建 |
| `run-build-test` | Run Tests Build | `test/` 下的 `.h/.c/.cpp/.sh/.cmake` | `bash build.sh ut --skip-run-tests` | 提交测试代码时编译 UT(不运行) |
| `clang-format` | Run clang-format check | 所有 `.h/.c/.cpp` | `clang-format -style=file -i` | 自动格式化源码 |
| `clang-tidy` | Run clang-tidy check | 非 test/ 下的 `.h/.c/.cpp` | `clang-tidy -p=cmake-build-release -header-filter=.* --fix` | 静态检查 + 自动修复(Release 编译数据库) |
| `clang-tidy-test` | Run clang-tidy check for test files | `test/UT/` 下的 `.h/.c/.cpp` | `clang-tidy -p=cmake-build-debug --fix` | 测试文件静态检查(Debug 编译数据库) |

**关键设计**:
- 源码用 `cmake-build-release`,测试用 `cmake-build-debug`(与"release for src, debug for test"一致)
- clang-tidy 启用 `--fix` 自动修复
- 构建类钩子 `pass_filenames: false`(避免传文件名给 build.sh)

### 11.2 编译数据库

`CMAKE_EXPORT_COMPILE_COMMANDS ON` 生成 `compile_commands.json`,供 LSP 和 clang-tidy 使用:

| 构建类型 | 编译数据库位置 |
|----------|----------------|
| Release | `cmake-build-release/compile_commands.json` |
| Debug | `cmake-build-debug/compile_commands.json` |

**LSP 配置**:根据当前活动构建配置,指向对应的构建目录。

## 13. 编码最佳实践

### 13.1 现代 C++ 特性(modernize 强制)

```cpp
// 使用 using 而非 typedef
using UbseResult = uint32_t;

// 使用 nullptr 而非 NULL 或 0
void *ptr = nullptr;

// 使用 override 标注虚函数重写
class Derived : public Base {
public:
    void Foo() override;
};

// 使用 emplace_back 而非 push_back(性能)
vec.emplace_back(args...);

// 使用 make_unique/make_shared
auto ptr = std::make_unique<Foo>();
```

### 13.2 禁用项

| 禁用项 | 替代方案 | 检查规则 |
|--------|----------|----------|
| C 风格转换 `(int)x` | `static_cast<int>(x)` | `cppcoreguidelines-pro-type-cstyle-cast` |
| `reinterpret_cast` | 避免使用,必要时审查 | `cppcoreguidelines-pro-type-reinterpret-cast` |
| `typedef` | `using` | `modernize-use-using` |
| `NULL` / `0` 作为空指针 | `nullptr` | `modernize-use-nullptr` |
| 全局可变变量 | `thread_local` 或封装 | `cppcoreguidelines-avoid-non-const-global-variables` |
| 头文件中定义函数 | 仅声明,定义放 .cpp | `misc-definitions-in-headers` |
| 重复 include | 删除重复 | `readability-duplicate-include` |
| 多余的字符串初始化 | 直接构造 | `performance-redundant-string-init` |

### 13.3 安全编码

| 要求 | 实现 |
|------|------|
| 栈保护 | `-fstack-protector-strong`(编译选项强制) |
| 源码加固 | `-D_FORTIFY_SOURCE=2`(Release 模式) |
| 栈不可执行 | `-Wl,-z,noexecstack`(链接器选项) |
| GOT 只读 | `-Wl,-z,relro,-z,now`(链接器选项) |
| 内存安全 | 使用 securec 库(`memset_s`、`strncpy_s` 等)替代不安全 C 函数 |
| 整数溢出检测 | Debug 模式 `-ftrapv` |

### 13.4 内存管理

- 优先使用智能指针(`std::unique_ptr`、`std::shared_ptr`)
- 使用 `std::make_unique` / `std::make_shared` 创建智能指针
- 避免裸 `new` / `delete`
- 使用 RAII 管理资源(锁、文件句柄、socket)

### 13.5 错误处理

- 使用错误码返回(非异常),错误码定义在 [ubse_error.h](../../src/include/ubse_error.h)
- 错误码命名 UPPER_CASE,以 `UBSE_` 前缀
- 日志记录错误时使用 `UBSE_LOG_ERROR`,包含错误码与上下文
