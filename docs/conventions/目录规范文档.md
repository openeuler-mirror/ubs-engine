## 2. 源码目录(`src/`)

源码采用**分层架构**,自底向上分为:框架层 → 控制器层 → API 层 → 插件层 → SDK 层。

### 2.1 整体结构

```
src/
├── ubse_main.cpp               # 主守护进程入口
├── CMakeLists.txt              # 源码 CMake 入口
├── include/                    # 对外公共头文件(详见 2.2)
├── framework/                  # 框架层(详见 2.3)
├── controllers/                # 控制器层(详见 2.4)
├── api_server/                 # 北向 API 服务层(详见 2.5)
├── sdk/                        # 多语言 SDK(详见 2.6)
├── cli/                        # 命令行接口(详见 2.7)
├── adapter_plugins/            # 适配器插件(详见 2.8)
├── addons/                     # 扩展插件(详见 2.9)
├── container/                  # 容器化辅助(ubse_helper DaemonSet)
├── ras/                        # 故障可靠性处理(详见 2.10)
└── message/                    # 基础消息定义(详见 2.11)
```

### 2.2 公共头文件(`src/include/`)

存放跨模块共享的对外头文件,供 SDK、外部模块、内部模块共同引用。

**核心规则**(详见 2.2.2):`src/include/` 下的目录结构**必须镜像 `src/` 的模块目录层级**,不得按模块名平铺;根目录**禁止直接存放头文件**。

#### 2.2.1 头文件按 `src/` 目录层级镜像归档

`src/include/` 的子目录与 `src/` 的子目录**一一对应**,头文件按其在 `src/` 中的所属模块归档到镜像路径下:

```
src/include/
├── common/                     # 【特殊】跨模块共享基础定义(无 src/ 对应物)
│   ├── ubse_def.h              # 基础类型定义
│   ├── ubse_common_def.h       # 公共定义
│   ├── ubse_const_def.h        # 常量定义
│   ├── ubse_error.h            # 错误码定义
│   ├── ubse_module.h           # 模块基类
│   ├── ubse_base_message.h     # 消息基类
│   └── ubse_service_registry.h # 服务注册
├── framework/                  # 镜像 src/framework/
│   ├── cert/                   # 证书校验(ubse_cert_def.h / ubse_cert_validator.h)
│   ├── com/                    # 通信(ubse_com.h / ubse_com_op_code.h)
│   ├── event/                  # 事件(ubse_event.h / ubse_event_module.h)
│   ├── ha/                     # 高可用选举(ubse_election.h)
│   ├── log/                    # 日志(ubse_logger.h / ubse_logger_audit.h / ubse_logger_module.h)
│   ├── misc/                   # 杂项工具(ubse_dl_manager.h / ubse_future_mgr.h / ubse_logging_lock_guard.h / ubse_sequence_counter.h)
│   ├── security/               # 安全(ubse_security.h)

│   ├── timer/                  # 定时器(ubse_timer.h)
│   ├── trace_context/          # 链路追踪(trace_context.h)
│   ├── vip/                    # VIP 管理(ubse_vip_http_server.h)
│   └── filter_chain/           # 责任链(ubse_filter_chain.h)
├── controllers/                # 镜像 src/controllers/(仅保留现有头文件,不再新增)
│   ├── mem/                    # 内存控制器(ubse_mem_controller.h)
│   ├── node/                   # 节点管理(ubse_node.h / ubse_node_controller.h / ubse_node_mgr.h / ubse_node_mgr_def.h)
│   ├── ssu/                    # SSU 控制器
│   └── urma/                   # URMA 控制器
├── adapter_plugins/            # 镜像 src/adapter_plugins/

│   ├── mti/                    # MTI(ubse_mti_*.h / ubse_smbios.h / ubse_topology_interface.h)

│   └── urma/                   # URMA UVS(ubse_urma_uvs.h)
├── api_server/                 # 镜像 src/api_server/(ubse_api_server.h / ubse_api_server_def.h)
├── ras/                        # 镜像 src/ras/(ubse_ras.h / ubse_ras_module.h)
├── message/                    # 镜像 src/message/(ubse_base_message.h)

    ├── node/                   # 节点服务契约
    ├── ssu/                    # SSU 服务契约(ubse_ssu_service.h)
    └── urma/                   # URMA 服务契约

**镜像关系对照**:

| `src/` 下的模块路径 | `src/include/` 下的镜像路径 |
|---------------------|-----------------------------|
| `src/framework/log/` | `src/include/framework/log/` |
| `src/framework/com/` | `src/include/framework/com/` |
| `src/controllers/ssu/` | `src/include/controllers/ssu/` |
| `src/adapter_plugins/mti/` | `src/include/adapter_plugins/mti/` |
| `src/api_server/` | `src/include/api_server/` |
| `src/ras/` | `src/include/ras/` |
| `src/message/` | `src/include/message/` |

**两个特殊目录**(不直接镜像 `src/`,但有明确职责):
- `src/include/common/`:跨模块共享的基础类型/常量/错误码/基类,无对应 `src/` 模块
- `src/include/plugin_services/<module>/`:控制器对外服务契约的逻辑分组,供 SDK 与内部模块解耦引用(详见 2.2.3)

**`controllers/` 目录约束(重要)**:

`src/include/controllers/<module>/` 为**冻结目录**,仅保留现有头文件(如 `ubse_mem_controller.h`、`ubse_node_*.h`、`ubse_ssu_def.h` 等),**不再新增头文件**。

| 项 | 规则 |
|----|------|
| 现有头文件 | 保持现状,不做迁移,可继续修改维护 |
| 新增控制器对外接口 | 一律归档到 `src/include/plugin_services/<module>/`,**禁止**放入 `controllers/<module>/` |
| 新增控制器内部数据结构/枚举 | 若需对外暴露,同样归档到 `src/include/plugin_services/<module>/` |
| 新增控制器实现细节头文件 | 保留在 `src/controllers/<module>/` 源码目录内,不放入 `src/include/` |

**判定流程**(新增控制器头文件时):
1. 是否为对外暴露的服务契约/接口/数据结构? → 是:归档到 `src/include/plugin_services/<module>/`
2. 是否为控制器内部实现细节? → 是:保留在 `src/controllers/<module>/` 源码目录
3. **禁止**向 `src/include/controllers/<module>/` 新增任何头文件

**历史遗留说明**:`src/include/controllers/` 下现有的 `ubse_mem_controller.h`、`ubse_node_*.h`、`ubse_ssu_def.h` 等属于历史遗留,保持现状不强制迁移;但新代码必须遵循上述约束。

#### 2.2.2 头文件归档规则

**规则一(镜像层级)**:`src/include/` 的子目录**必须镜像 `src/` 的模块目录层级**,禁止按模块名平铺。

| 错误(平铺) | 正确(镜像层级) |
|--------------|------------------|
| `src/include/log/ubse_logger.h` | `src/include/framework/log/ubse_logger.h` |
| `src/include/com/ubse_com.h` | `src/include/framework/com/ubse_com.h` |
| `src/include/ssu/ubse_ssu_def.h` | `src/include/controllers/ssu/ubse_ssu_def.h` |
| `src/include/mem/ubse_mem_controller.h` | `src/include/controllers/mem/ubse_mem_controller.h` |
| `src/include/mti/ubse_mti_def.h` | `src/include/adapter_plugins/mti/ubse_mti_def.h` |

**规则二(禁放根目录)**:`src/include/` 根目录**禁止直接存放头文件**,所有头文件必须归档到镜像子目录或特殊目录。

**归档方法**:头文件归属按"其在 `src/` 中的源码所属层级"判定:

| 头文件来源 | 归档目录 | 示例 |
|------------|----------|------|
| `src/framework/<module>/` 下的模块 | `src/include/framework/<module>/` | `src/include/framework/log/ubse_logger.h` |
| `src/controllers/<module>/` 下的**现有**模块头文件 | `src/include/controllers/<module>/`(冻结,仅保留现有) | `src/include/controllers/ssu/ubse_ssu_def.h`(历史遗留) |
| `src/controllers/<module>/` 下的**新增**对外接口 | `src/include/plugin_services/<module>/`(详见 2.2.3) | `src/include/plugin_services/ssu/ubse_ssu_service.h` |
| `src/adapter_plugins/<module>/` 下的模块 | `src/include/adapter_plugins/<module>/` | `src/include/adapter_plugins/mti/ubse_mti_def.h` |
| `src/api_server/` 下的模块 | `src/include/api_server/` | `src/include/api_server/ubse_api_server.h` |
| `src/ras/` 下的模块 | `src/include/ras/` | `src/include/ras/ubse_ras.h` |
| `src/message/` 下的模块 | `src/include/message/` | `src/include/message/ubse_base_message.h` |
| 控制器对外服务契约(抽象基类) | `src/include/plugin_services/<module>/` | `src/include/plugin_services/ssu/ubse_ssu_service.h` |
| 跨模块共享的基础类型/错误码/基类 | `src/include/common/` | `src/include/common/ubse_error.h` |

**判定流程**:
1. 头文件是否对应 `src/` 下某层级的源码模块?
   - 控制器模块(`src/controllers/<module>/`):**新增**对外接口 → `src/include/plugin_services/<module>/`;**现有**头文件 → 保持 `src/include/controllers/<module>/`(冻结)
   - 其他模块 → 归档到镜像路径 `src/include/<src层级>/<module>/`
2. 头文件是否为控制器对外服务契约? → 是:归档到 `src/include/plugin_services/<module>/`
3. 头文件是否为跨模块共享的基础定义? → 是:归档到 `src/include/common/`
4. 以上都不是 → 评估是否应归入某现有镜像目录,或新建与 `src/` 一致的镜像子目录

**新增头文件归档清单**(代码评审时检查):
- [ ] 头文件未直接放在 `src/include/` 根目录
- [ ] 头文件已归档到 `src/` 的镜像路径下(如 `framework/<module>/`、`adapter_plugins/<module>/`)
- [ ] 头文件未按模块名平铺(如未放在 `src/include/log/`、`src/include/ssu/` 等平铺目录)
- [ ] **控制器新增头文件**已归档到 `src/include/plugin_services/<module>/`,**未**放入 `src/include/controllers/<module>/`(冻结目录)
- [ ] 若新建子目录,目录路径与 `src/` 下的层级路径一致

**历史遗留说明**:当前 `src/include/` 根目录存在部分未归档的头文件(如 `ubse_def.h`、`ubse_logger.h`、`ubse_mem_controller.h` 等),属于历史遗留。新代码必须遵循镜像归档规则,历史头文件在重构时按镜像路径逐步迁移。

#### 2.2.3 服务契约目录(`src/include/plugin_services/<module>/`)

**特殊目录**:`plugin_services/` 是 `src/include/` 中的逻辑分组目录,不直接镜像 `src/` 的层级,专门存放各控制器的**对外服务契约**(抽象基类 + 数据结构),供 SDK 与内部模块解耦引用。

**重要定位**:`plugin_services/` 是**新增控制器对外接口的唯一归档入口**。控制器新增的服务契约、对外数据结构、对外枚举等头文件,**必须**归档到 `src/include/plugin_services/<module>/`,不得放入 `src/include/controllers/<module>/`(该目录已冻结,详见 2.2.1)。

```
plugin_services/
├── mem/        # 内存服务契约(ubse_mem_service.h / ubse_mem_service_def.h)
├── node/       # 节点服务契约
├── ssu/        # SSU 服务契约(ubse_ssu_service.h)
└── urma/       # URMA 服务契约
```

**命名规范**:服务契约文件命名为 `ubse_<module>_service.h`,内含抽象基类 `Ubse<Module>Service`。服务契约配套的数据结构/枚举头文件命名为 `ubse_<module>_service_def.h`。

**归档内容范围**:

| 头文件类型 | 是否归档到 `plugin_services/` | 示例 |
|------------|-------------------------------|------|
| 控制器对外服务契约(抽象基类) | 是 | `ubse_ssu_service.h` |
| 服务契约配套的数据结构/枚举 | 是 | `ubse_mem_service_def.h` |
| 控制器新增的对外接口/数据结构 | 是 | 新增控制器对外暴露的所有头文件 |
| 控制器内部实现细节头文件 | 否(保留在 `src/controllers/<module>/` 源码目录) | `*_impl.h`、`*_scheduler.h` 等 |
| 现有 `controllers/<module>/` 下的历史头文件 | 否(保持现状,不迁移) | `ubse_mem_controller.h`、`ubse_ssu_def.h` |

**与 `controllers/<module>/` 的关系**:
- `src/include/controllers/<module>/`:**冻结目录**,仅保留现有头文件(如 `ubse_ssu_def.h`、`ubse_mem_controller.h`),不再新增
- `src/include/plugin_services/<module>/`:**新增控制器对外接口的唯一入口**,是 SDK 与内部模块解耦引用的入口

### 2.4 控制器层(`src/controllers/`)

资源控制器,具体业务核心层。**新增资源控制器在此目录下创建子目录**。

| 子目录 | 职责 |
|--------|------|
| `include/` | 控制器公共头(mem 配置、常量、定义) |
| `mem/` | 内存控制器(内存池化核心) |
| `node/` | 节点控制器(节点拓扑、master/agent、collector) |
| `ssu/` | SSU 控制器(共享存储单元,详见 2.4.1) |
| `npu/` | NPU 控制器 |
| `urma/` | URMA 控制器(统一远端内存访问) |

#### 2.4.1 控制器子模块结构规范(以 `ssu/` 为例)

新增控制器应遵循以下子模块组织:

```
controllers/<module>/
├── <module>_controller_module.{h,cpp}    # 模块入口与生命周期
├── <module>_service_imp.{h,cpp}          # 服务实现(业务编排)
├── <module>_scheduler.{h,cpp}            # 调度器(责任链/算法)
├── <module>_collector.{h,cpp}            # 收集器(设备/资源采集)
├── <module>_http_handler.{h,cpp}         # HTTP 路由处理器
├── <module>_rpc_processor.{h,cpp}        # 跨节点 RPC 处理器
├── <module>_reservation_mgr.{h,cpp}      # 预留管理(可选)
├── debt/                                 # 借欠账管理(可选)
│   └── <module>_debt_ledger.{h,cpp}
├── ipc/                                  # IPC 处理器(可选)
│   ├── <module>_ipc_message_handler.*
│   └── <module>_ipc_obj_message_handler.*
└── message/                              # 消息定义(跨节点通信)
    ├── <module>_<op>_msg.h               # 操作消息(alloc/free/perm 等)
    └── <module>_sync_resp_msg.h
```

### 2.5 北向 API 服务层(`src/api_server/`)

对外暴露 RESTful/HTTP API,管理鉴权与对象。

| 文件 | 职责 |
|------|------|
| `ubse_api_server.cpp` | API 服务主入口 |
| `ubse_api_server_module.*` | API 模块封装 |

**注意**:鉴权管理器与对象管理器归档在框架层 IPC 模块下,不在 `src/api_server/` 内:
- `src/framework/ipc/auth/ubse_api_server_auth_manager.cpp` — 鉴权管理器实现
- `src/framework/ipc/auth/ubse_api_server_object_manager.cpp` — 对象管理器实现
- `src/framework/ipc/include/ubse_api_server_{auth_manager,object_manager}.h` — 对外头文件

### 2.6 SDK 层(`src/sdk/`)

供外部消费者调用引擎能力,**多语言并行**。

```
sdk/

#### 3.1.3 归档方法与判定流程

**归档方法**:测试文件归属按"被测源码在 `src/` 中的所属层级"判定:

| 被测源码路径 | 测试文件归档目录 | 示例 |
|--------------|------------------|------|
| `src/framework/<module>/` | `test/UT/framework/<module>/` | `test/UT/framework/log/test_ubse_logger.cpp` |
| `src/controllers/<module>/` | `test/UT/controllers/<module>/` | `test/UT/controllers/ssu/test_ubse_ssu_scheduler.cpp` |
| `src/adapter_plugins/<module>/` | `test/UT/adapter_plugins/<module>/` | `test/UT/adapter_plugins/mti/test_ubse_lcne_module.cpp` |
| `src/addons/<plugin>/` | `test/UT/addons/<plugin>/` | `test/UT/addons/rmrs/test_rack_mempooling_plugin.cpp` |
| `src/api_server/` | `test/UT/api_server/` | `test/UT/api_server/test_ubse_api_server.cpp` |
| `src/ras/` | `test/UT/ras/` | `test/UT/ras/test_ubse_ras.cpp` |
| `src/sdk/<lang>/` | `test/UT/sdk/<lang>/` | `test/UT/sdk/c/test_ubse_sdk_c.cpp` |
| `src/message/` | `test/UT/message/` | `test/UT/message/test_ubse_base_message.cpp` |

**判定流程**(新增测试文件时):
1. 被测源码是否在 `src/` 下某层级? → 是:归档到镜像路径 `test/UT/<src层级>/<module>/`
2. 被测对象是否为跨模块的算法/工具? → 是:归档到 `test/UT/algorithm/`(特殊目录,详见 3.1.4)
3. 若 `src/` 下尚无对应模块目录,但被测对象明确属于某层级 → 按层级归档,并在 `src/` 下补齐模块目录

**新增测试文件归档清单**(代码评审时检查):
- [ ] 测试文件未直接放在 `test/UT/` 根目录
- [ ] 测试文件已归档到 `src/` 的镜像路径下(如 `framework/<module>/`、`controllers/<module>/`、`addons/<plugin>/`)
- [ ] 测试文件未按模块名平铺(如未放在 `test/UT/log/`、`test/UT/election/` 等平铺目录)
- [ ] 若新建子目录,目录路径与 `src/` 下的层级路径一致

## 11. 构建产物目录(`cmake-build-*/`)

构建时自动生成,不入库。

| Build Type | 目录名 | 用途 |
|------------|--------|------|
| Debug | `cmake-build-debug` | 调试构建(测试默认) |
| Release | `cmake-build-release` | 发布构建(默认) |

**产物分布**:

- `cmake-build-*/compile_commands.json` — LSP 与 clang-tidy 编译数据库

## 12. 新增模块归档规范

新增一个业务模块时,需在以下目录创建对应文件:

| 步骤 | 目录 | 文件/操作 |
|------|------|-----------|
| 1 | `src/controllers/<module>/` | 创建模块源码目录(详见 2.4.1) |
| 2 | `src/include/plugin_services/<module>/` | 创建控制器对外头文件(服务契约 + 对外数据结构/枚举,详见 2.2.3) |
| 3 | `src/adapter_plugins/<module>/` | 创建适配器(若需对接硬件) |
| 4 | `src/cli/<module>/` | 创建 CLI 命令(若需 CLI) |
| 5 | `src/sdk/c/include/` | 更新 C SDK 头文件(若需 SDK 暴露) |
| 6 | `src/sdk/{c,go,python}/` | 更新各语言 SDK 实现 |
| 7 | `test/UT/controllers/<module>/` | 创建 UT 测试(镜像源码结构) |
| 8 | `test/UT/adapter_plugins/<module>/` | 创建适配器 UT |
| 9 | `test/IT/` `test/PT/` `test/FUZZ/` | 创建 IT/PT/FUZZ 测试(按需) |
| 10 | `docs/design/modules/<module>/` | 创建三件套文档(需求/设计/测试);若含多个特性扩展,主体三件套在根目录,各特性按英文小写子目录归档(详见 4.1 模块文档子目录拆分规则) |
| 11 | `docs/design/images/modules/` | 存放设计文档图片 |
| 12 | `docs/design/README.md` | 更新文档索引 |
| 13 | `conf/` | 新增运行时配置(若需) |
| 14 | 各级 `CMakeLists.txt` | 更新构建配置 |

**重要约束**:
- **控制器对外头文件**一律归档到 `src/include/plugin_services/<module>/`,**禁止**在 `src/include/controllers/<module>/` 下新增头文件(该目录已冻结,详见 2.2.1)
- **控制器内部实现细节头文件**保留在 `src/controllers/<module>/` 源码目录内,不放入 `src/include/`
- **新增框架模块**(位于 `src/framework/<module>/`)的头文件应归档到 `src/include/framework/<module>/`,而非 `src/include/<module>/`
- **UT 目录必须镜像 `src/` 层级**(详见 3.1):新增框架模块的 UT 归档到 `test/UT/framework/<module>/`;新增控制器模块的 UT 归档到 `test/UT/controllers/<module>/`;新增扩展插件的 UT 归档到 `test/UT/addons/<plugin>/`。**禁止**按模块名平铺(如 `test/UT/<module>/`)

## 13.1 头文件归档规范

**核心规则**:`src/include/` 的目录结构**必须镜像 `src/` 的模块目录层级**,禁止按模块名平铺;根目录禁止直接存放头文件(详见 2.2.2)。

| 头文件类型 | 归档目录(镜像 `src/` 层级) | 示例 |
|------------|------------------------------|------|
| 框架模块专属接口 | `src/include/framework/<module>/` | `src/include/framework/log/ubse_logger.h` |
| 控制器**现有**头文件(冻结) | `src/include/controllers/<module>/`(仅保留现有,不新增) | `src/include/controllers/ssu/ubse_ssu_def.h`(历史遗留) |
| 控制器**新增**对外接口 | `src/include/plugin_services/<module>/`(详见 2.2.3) | `src/include/plugin_services/ssu/ubse_ssu_service.h` |
| 适配器插件接口 | `src/include/adapter_plugins/<module>/` | `src/include/adapter_plugins/mti/ubse_mti_def.h` |
| API/RAS/Message 模块接口 | `src/include/<对应src层级>/` | `src/include/api_server/ubse_api_server.h` |
| 控制器服务契约 | `src/include/plugin_services/<module>/` | `src/include/plugin_services/ssu/ubse_ssu_service.h` |
| 跨模块共享基础定义 | `src/include/common/` | `src/include/common/ubse_error.h` |

**禁止行为**:
- 禁止在 `src/include/` 根目录直接创建 `.h` 文件
- 禁止按模块名平铺(如 `src/include/log/`、`src/include/ssu/`、`src/include/com/` 均违规)
- 禁止将头文件归档到与 `src/` 层级不一致的目录
- 禁止新建与 `src/framework/` 或 `src/controllers/` 下层级不一致的镜像目录
- **禁止向 `src/include/controllers/<module>/` 新增头文件**(该目录已冻结,新增控制器对外接口一律放 `src/include/plugin_services/<module>/`)

**模块子目录命名**:镜像路径与 `src/` 下的层级路径保持一致(如 `framework/log/`、`framework/com/`、`controllers/mem/`、`controllers/ssu/`、`adapter_plugins/mti/`)。

**`controllers/` 冻结说明**:`src/include/controllers/<module>/` 下的现有头文件(如 `ubse_mem_controller.h`、`ubse_node_*.h`、`ubse_ssu_def.h`)保持现状,可继续修改维护,但**不得新增**;新增控制器对外接口一律归档到 `src/include/plugin_services/<module>/`(详见 2.2.1、2.2.3)。
